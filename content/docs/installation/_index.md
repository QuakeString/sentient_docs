SENTIENT runs on your own server, on site or in your data centre, and it keeps working without internet access. Pick the way of installing that fits the machine.

| Machine | Recommended | How SENTIENT runs |
|---|---|---|
| Windows 10 or later, Windows Server | [Platform Manager](/docs/installation/windows/) | Windows services |
| Linux server | [Platform Manager](/docs/installation/linux/) or [Docker](/docs/installation/docker/) | Docker containers, or native systemd services |
| Any machine you already run Docker on | [Docker](/docs/installation/docker/) | Docker containers |

## Choose the database

You choose the database once, during installation. You can change it later with the Platform Manager's **Migration** screen, which copies and checks all history.

| Database | Good for |
|---|---|
| **PostgreSQL** | Small and medium sites. This is the simplest choice, with the smallest footprint. |
| **PostgreSQL with TimescaleDB** | Long history in PostgreSQL. Time series are compressed and stored in time chunks. |
| **PostgreSQL with ClickHouse** | Large sites and high data rates. Telemetry history goes to ClickHouse, which stores it far more compactly and answers long time-range queries much faster. Everything else stays in PostgreSQL. |

## After installation

1. [Activate your licence](/docs/installation/licence/).
2. [Sign in for the first time](/docs/getting-started-guides/first-login/) and create a tenant.
3. Set up [backups](/docs/operations/backup-restore/).
4. Open only the [ports](/docs/operations/ports/) you need.
