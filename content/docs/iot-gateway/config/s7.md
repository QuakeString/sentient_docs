The **S7** connector reads and writes Siemens PLCs over S7comm, the protocol STEP 7 and TIA Portal use (ISO-on-TCP, TCP port **102**). It needs no Siemens software on the gateway machine. One connector can poll many PLCs; each PLC is a device in SENTIENT.

Supported: **S7-200**, **S7-200 SMART**, **LOGO!**, **S7-300**, **S7-400**, **S7-1200** and **S7-1500**, and S7-400H / S7-1500R/H redundant pairs.

## Prepare an S7-1200 or S7-1500

These CPUs refuse outside access until you allow it in TIA Portal:

1. In the CPU's properties, under **Protection & Security > Connection mechanisms**, tick **Permit access with PUT/GET communication from remote partner**.
2. For each data block you read, open its properties and clear **Optimized block access**, so its variables have fixed addresses (`DB1.DBD0` and so on).
3. Download the hardware and the blocks to the CPU.

S7-300 and S7-400 need nothing extra.

## Add a PLC

1. In SENTIENT, open the gateway, then **Connectors**, and add an **S7** connector (or open the one you have).
2. Under **S7 PLC Devices**, click **+**.
3. Fill in the connection:

   | Setting | Value |
   |---|---|
   | **Device Name** | The name of the device in SENTIENT, for example `Press 4 PLC` |
   | **Device profile** | The [device profile](/docs/user-guide/device-profiles/) it gets |
   | **Host**, **Port** | The PLC's IP address, port `102` |
   | **Rack**, **Slot** | Where the CPU sits. S7-300: rack 0, slot 2. S7-1200, S7-1500 and LOGO!: rack 0, slot 1. S7-400: see the hardware configuration |
   | **PLC Model** | The CPU family |
   | **Poll Period (ms)** | How often the values are read |
   | **Connect Attempts**, **Wait After Failed (ms)** | How hard to retry when the PLC does not answer |

4. Add the keys (below), click **Apply**, and save the connector.

## Addresses

Each key has a **Tag** (the key's name in SENTIENT) and an **Address**. Three notations work, so you can copy addresses from STEP 7, TIA Portal or WinCC as they are:

| Notation | Examples |
|---|---|
| SIMATIC | `DB1.DBX0.0` (bit), `DB1.DBB2` (byte), `DB1.DBW4` (word), `DB1.DBD8` (double word), `M0.0`, `MW100`, `I0.0`, `IW20`, `Q0.1`, `T15`, `C4`. A leading `%` from a TIA export is accepted |
| WinCC | `DB1,X0.0`, `DB1,B2`, `DB1,W4`, `DB1,INT6`, `DB1,DINT8`, `DB1,REAL12`, `DB1,S20.30` (a STRING of 30 bytes at 20). The operand gives the data type |
| German | `E0.0`, `EW20`, `A0.1`, `AW10`, `Z4` |

**Value Type** says how to read what is at the address: `bool`, `int8`, `uint8`, `int16`, `uint16`, `int32`, `uint32`, `float32`, `float64` or `string`. The width comes from the address: `DB1.DBD0` with `int32` reads a DINT, with `float32` a REAL. A double word with no value type is read as a REAL.

The IEC time types work too: `DB1,DT32` (DATE_AND_TIME), `DB1,DATE56`, `DB1,TOD60` (TIME_OF_DAY), `DB1,TIME48`, `DB1,S5T44` and `DB1,WSTRING64.16` (a WSTRING of 16 characters). Durations (`TIME`, `S5TIME`) arrive as milliseconds; dates and times arrive as text such as `2026-11-07T14:05:00`, without a time zone.

**Timers and counters** (`T5`, `C4`) arrive as milliseconds and as the count. A numeric value type gives the raw word instead.

**Modifier** scales a value (multiply, divide, add or subtract), or maps a raw range to an engineering range, for example 0 to 27648 to 0 to 100 %.

## Import tags from a file

Click **Import Tags** in the keys panel and choose an `.xlsx`, `.csv` or `.ods` file, for example a TIA Portal tag table export. Map the columns, check the count of valid and invalid rows, and click **Import N Tags**. Rows whose address is already on the device are skipped unless you turn on **Import duplicate addresses**. You can also edit all keys at once in the [key sheet](/docs/iot-gateway/key-sheets/).

## Write to the PLC

Add keys under **RPC Methods** (a dashboard calls them with the value) or **Attribute Updates** (changing a shared attribute writes it), each with an address and value type. Or tick read keys and use [Add to RPC write](/docs/iot-gateway/rpc-write/).

- A STRING write keeps the length the address declares. A longer value is refused, not cut.
- A boolean accepts `true`, `false`, `on`, `off`, `yes`, `no`, `1` or `0`. Anything else is refused.
- A timer written as `2500` sets 2.5 s.

## PLC clock

**Time synchronization** reads the PLC's clock and sets it from the gateway. Click **Read and set the PLC clock** once by hand to check that the CPU accepts clock writes; after that, **Auto sync** pushes the gateway's time every **Interval (s)**. The gateway sends its local time, because a CPU has no time zone.

## Redundant pairs

For an S7-300, S7-400 or S7-1500 redundant system, turn on **Enable Redundancy** under **Redundancy (R/H System)** and enter the **Standby Host**, **Port**, **Rack** and **Slot**. The gateway keeps both connections open, checks the standby every **Heartbeat Interval (ms)**, and switches after **Failure Threshold** failures in a row (the log says `S7 FAILOVER`). Writes go to whichever CPU is answering. Set the threshold to `1` to switch at the first failure.

## When something is wrong

| What you see | What to do |
|---|---|
| The PLC refuses the connection on an S7-1200/1500 | Allow PUT/GET access (see above) |
| One key never reports, the others do | Its address is outside the data block, or the block uses optimized access. The log names the key and the CPU's reason once, then at most once a minute |
| Every value of a data block is wrong or missing | **Optimized block access** is on for that block |
| The connection drops on an S7-300 with many keys | Fixed in the Rust gateway: reads are split to the PLC's packet size. Update the gateway |
| Wrong values after switching from the Python gateway | A key with a **Value Type** on a dot address (`DB1.DBD0`) is now read with that type. The new values are the correct ones |
